Data trees

A list handles one row of things. A building has rows of rows: nodes per floor, beams per bay per floor. Grasshopper stores those as a tree. Trees are the hardest idea in the course and the one that separates people who can use Grasshopper at work from people who cannot.

{{sn}}What a tree is

By the end you can read a tree's structure in a Param Viewer and say how many branches it has and how long each one is.

Idea

A data tree (データツリー) is a set of lists. Each list is a branch, and each branch has an address called a path, written in curly brackets: {0}, {1}, {0;2}. A plain list is a tree with one branch, {0}.

Trees appear on their own. Give Divide Curve three curves and ask for 4 segments each. It returns 15 points, and it keeps them in three branches of 5 so you still know which point belongs to which curve.

Example

{0;0}   N = 5     points on curve 0
  0  point
  1  point
  2  point
  3  point
  4  point
{0;1}   N = 5     points on curve 1
{0;2}   N = 5     points on curve 2

Read a path from the right. The last number is the newest level: here it is the index of the curve. The 0 in front is left over from the input list. Simplify Tree removes the part all paths share, which turns these into {0}, {1}, {2}. The live examples on this page show simplified paths.

The rule that makes trees useful: a component runs once per branch. Polyline given this tree draws three polylines, one through each branch.

In Rhino

  1. Draw three separate lines in Rhino. Reference all three in one Curve parameter with Set Multiple Curves.
  2. Wire it into Divide Curve with N = 4, then wire the P output into a Param Viewer (Params, Util) and into a panel.
  3. Read the paths. Then right-click the P output, choose Simplify, and read them again.
  4. Wire P into Polyline. Count the polylines.

{{sn}}Flatten, Graft and Flip Matrix

By the end you can reshape a tree on purpose, and recognise the two classic mistakes when you see them.

Idea

OperationWhat it doesTypical use
FlattenPours every branch into one listCounting, or sending all members to the analysis at once
GraftGives every item its own branchMaking a component treat each item separately
SimplifyRemoves the shared part of the pathsTidying paths so two trees can match
Flip MatrixSwaps rows and columnsTurning "by floor" into "by column line"

All four exist as components under Sets, Tree. Flatten, Graft and Simplify are also one right-click away on any input or output, and a small icon appears on the port when one is active.

Try it here

In Rhino

  1. Build a grid of points with one branch per floor. The quickest way is in the next session. For now, use your three divided curves from Session {{n:s10}} as the three floors.
  2. Wire the points into Polyline four times, each through a different operation, and compare.
  3. With Flip Matrix, check the Param Viewer before and after: the number of branches and the length of each branch swap places.

Watch out: Flip Matrix needs a full rectangle

Flip Matrix expects every branch to have the same number of items. If one floor has a column missing, the rows no longer line up, and the result is not what you expect. Check branch lengths in a Param Viewer first.

{{sn}}A multi-storey frame, organised by floor

By the end you have a frame for any number of storeys and bays, with beams stored by floor and columns stored by grid line.

Idea

Grafting one input is how you build a tree deliberately. Give Construct Point a plain list of X values and a grafted list of Z values. Each Z sits alone in its own branch, so the component runs once per level, and each run pairs that one Z with the whole X list. Out comes one branch of nodes per level.

Example

  1. Nodes by level: as in the figure.
  2. Beams (梁): within each branch, Line from the nodes to the same nodes through Shift List, with Shortest List. Because a component runs once per branch, one Line component draws the beams of every floor. Remove the ground branch first with Tree Branch or by starting the Z series at the first floor.
  3. Columns (柱): Flip Matrix on the nodes, so each branch is one grid line from bottom to top. Then the same Shift List trick draws every column.

The output is two trees. Beams are grouped by floor, columns by grid line. That grouping is what lets you say "floors 1 to 3 get H-400, floors 4 to 6 get H-350" later.

Try it here

In Rhino

  1. Build the frame with four sliders: storeys, bays, storey height (階高) and bay width (スパン).
  2. Put a Param Viewer on the beams and on the columns. Confirm the branch counts match the live example.
  3. Use Tree Branch with path {0} to isolate the first-floor beams, and give them a different preview colour with Custom Preview.
